# APP 中英語系（i18n）規範

2026-10-05 建立（Phase A）。給接手抽字串的 agent 與日後維護者。設計決策來源：
`..\CONTINUE_2026-10-05_APP_I18N.md`。

- 預設**繁體中文**，不跟隨手機系統語言；「更多」→「語言」切換，存
  shared_preferences `app_locale`（`zh`／`en`），切換立即生效、不必重開。
- 只有 **APP 畫面**跟著語言；**上傳後台與匯出（分享、複製）的報告維持中文**（§6）。
- 官方 `flutter gen-l10n`（ARB）。範本：`lib/presentation/gateway_status_page.dart`
  （widget 層）、`lib/core/mqtt_target.dart`（無 context 層＋報告維持中文）。

## 1. 檔案配置

| 路徑 | 說明 |
|---|---|
| `lib/l10n/parts/<area>_zh.arb`、`<area>_en.arb` | **唯一要手改的地方**。一個分區一對檔 |
| `lib/l10n/app_zh.arb`、`app_en.arb` | `tools/merge_l10n.py` 產生，commit，不要手改 |

| `tools/find_cjk_strings.py` | 找殘留中文字面量（Phase C sweep 用） |
| `test/l10n_test.dart` | ARB 一致性、語言切換與持久化、範本檔、邏輯代碼 |

| `test/en_layout_test.dart` | 英文版面抽查（360x640、字級 1.0／1.3、真字型；§8.6） |

locale：APP 字串只有 `zh`（繁中內容）與 `en` 兩組。`MaterialApp.locale` 用
`zh_Hant_TW`（`appZhLocale`），讓 Material 內建字串（返回、複製、日期選擇器）
也是繁體；gen-l10n 只看 languageCode，所以仍對到 `AppLocalizationsZh`。

## 2. 改字串的流程

```powershell
# 1. 編輯 lib/l10n/parts/<area>_zh.arb 與 <area>_en.arb（兩個一起改）
py -3 -X utf8 tools/merge_l10n.py          # 2. 合併（有錯會列出並不寫檔）
flutter gen-l10n                           # 3. 產生 AppLocalizations
flutter analyze                            # 4.
flutter test test/l10n_test.dart           # 5. 再跑受影響的測試
py -3 -X utf8 tools/merge_l10n.py --check --check-buttons  # 交付前：exit 0 才算一致
```

`--check-buttons`：句子裡提到的按鈕——en 的 `[...]`、zh 的〔…〕——必須與某個 key 的
完整值（按鈕 label）一字不差（ICU plural 各分支、`{x}` 代入都算）。改按鈕 label 時
要一起改所有提到它的句子。zh 的「…」也用來引述狀態文字，不在檢查範圍；
`commissioning_wifiResetGoHint`、`controller_starApply` 這類用「」引述按鈕的句子請人工對照。

`flutter pub get`／`flutter run`／`flutter build` 也會自動跑 gen-l10n，但**不會**跑
merge，所以改 parts 後一定先 merge。commit 時 parts、`app_*.arb`、
`app_localizations*.dart` 一起進。

## 3. key 命名

- `<area>_<lowerCamelCase>`，area＝分區檔名（lowerCamelCase、不含底線）。
  例：`gatewayStatus_nearbyEmpty`、`mqttTarget_failBusy`。合併腳本會擋前綴不符。
- 名稱描述**用途**而非內容：`_title`、`_hint`、`_empty`、`_failXxx`、`_confirmButton`。
- 同一句話只建一個 key；別的檔要用就 import 原本的 getter／函式，不要在另一分區
  再建一份。
- 通用字一律用 `common_*`（確定、取消、關閉、重試、返回、繼續、完成、稍後、略過、
  詳細資訊、知道了、未知、逾時、列舉分隔符 `common_listSeparator`「、」／", "…）。
  Phase C 已把各分區暫放的 18 個整併進 `common`。新增前先跑
  `merge_l10n.py --report-duplicate-values` 看有沒有相同的 zh 值。
- 其餘 zh 值相同的 key（約 50 組，例如 `controller_ptuNoResponse`／
  `protocol_ptuNoResponse`、按鈕在兩個畫面各一份）是不同語境刻意分開，英文可依語境
  不同；改其中一個時順便看另一個要不要一起改。
- 需要給翻譯者的說明寫在 zh 檔的 `@key.description`（英文寫即可）。en 檔不必寫
  `@key`，合併時以 zh 的 metadata 為準。

## 4. placeholders、數字、多行

```json
"gatewayStatus_name": "站 {site} 閘道器 {gateway}",
"@gatewayStatus_name": {
  "placeholders": { "site": {"type": "int"}, "gateway": {"type": "int"} }
},
"controller_retryCount": "{count, plural, other{重試這 {count} 台}}",
"@controller_retryCount": { "placeholders": { "count": {"type": "int"} } }
```

en：`"{count, plural, =1{Retry this one} other{Retry these {count}}}"`。

- 每個 `{name}` 都要在 zh 的 `placeholders` 宣告；zh、en 使用的 placeholder 集合
  必須相同（`test/l10n_test.dart` 會檢查）。
- **數量**：英文需要單複數就用 ICU `plural`（zh 只寫 `other`）。
- **int 不加 `format`**：直接插值、不加千分位（站號、閘道器編號、埠號、PTU #n）。
  埠號、版本號、MAC、IP、URL 一律用 `String`。
- **日期時間**：在 Dart 先格式化成字串（例 `09-28 14:03`）再傳 `String`，
  不要用 `DateTime` placeholder（會依語系換格式，現場畫面與舊測試不一致）。
- **整句放進 ARB**，不要在 Dart 拼句子片段（英文語序不同）。例外：純技術尾巴
  （`[endpoint · detail]`、`dBm`、`\n[set_mqtt_target · code]`）可留在 Dart。
- **多行**：ARB 值內用 `\n`；原本 Dart 用 `'…'\n'…'` 相鄰字串拼成一句的，合成一個值。
- 不要在值裡放字面 `{`、`}`（會被當成 placeholder）；〔〕「」、全形標點照用。
- 英文文案：短句、現場工程師看得懂、動詞開頭（`Tap [Rescan]`、`Move closer`）；
  按鈕名用方括號 `[Retry]` 對應中文的〔重試〕。

## 5. 哪一層用哪個存取器

| 位置 | 用法 |
|---|---|
| widget `build` 內 | `final l10n = context.l10n;` 然後 `l10n.xxx`（會訂閱語言變更） |
| application／core／data（無 context） | `L10n.current.xxx` |
| 上傳後台、匯出報告 | `L10n.zh.xxx`（固定中文；見 §6） |
| 測試 | 預設就是繁中；要英文用 `useLanguage(AppLanguage.en)` |

- 既有 **top-level 常數被別檔或測試引用**時：保留同名，`const x = '…';` 改成
  `String get x => L10n.current.area_key;`；呼叫端拿掉 `const`（`const Text(x)` →
  `Text(x)`）。這樣測試的 `find.text(x)` 不用改。範本：`gateway_status_page.dart` 開頭。
- 函式產生文字（`String fooText(int n) => '…$n…'`）：保留函式簽名，內部改
  `L10n.current.area_foo(n)`。
- `context.l10n` 在樹上沒有 delegates 時（既有測試自建的 MaterialApp）會退回
  `L10n.current`，不會丟例外。
- 切換語言時 `GatewayApp` 先換 `L10n.current` 再把整棵樹標記重建，所以 build
  裡讀 top-level getter 也會更新。但**已存進 state 的文字**（controller 的
  `message`、`error`、`results[mac]` 等）是產生當下的語言，切換後不會重翻——
  這是預期行為，下一次產生就是新語言。

## 8. 常見陷阱

1. **`const` 不能包 l10n**：`const Text(l10n.x)`、`const _Note(text: x)` 都不行；
   把 `const` 往內移到不含字串的子 widget（範本 `_nearbySection`）。
2. **邏輯不要比對畫面文字**。Phase A 已改三處：
   - `rescue_code`：救援代碼在失敗當下記進 `CommissionState.assignFailCodes`
     （`ptuFailRescueCode(error)`、比對不符＝`ptuWrongDevice`），不再從原因文字反推。
   - `assign_progress`：`assignResultKindOf(result)` → `AssignResultKind`，跨所有語言
     比對 `assign_notAssignedLink`／`assign_assigningResult`。
   - `'逾時'`：`GatewayFailure.network(detail: networkTimeoutDetail)` ＋
     `isNetworkTimeout`；畫面括號內顯示 `common_timeout`。

   **Phase B／C 已處理**（改旗標、列舉或結構化資料）：
   - `field_report.dart` `sessionRescueCode`：`state.noGatewayFound`（`MessageKind`）；
     `_assignOf`：`state.pendingReadbackOf(mac)`。原本的 `isGatewayNotFoundMessage`、
     `isPendingReadbackResult` 與 `fieldReport_gatewayNotFoundPrefix` 已刪除。
   - `gateway_discovery.dart` `gatewayBackendNoteFor(BackendPresence)`：卡片用
     `backendPresenceKind(...)` 列舉，不比對短語。
   - `commissioning_page.dart` 完成頁訊息：`s.messageKind != MessageKind.verified &&
     !s.dataStreaming`（`_isDataFlowingMessage` 刪除）；上傳列 `upload.uploading`；
     報告標題「模擬」：`ref.watch(linkProvider).demo`（與 controller 寫「模擬安裝報告」
     同源），不再 `startsWith('模擬')`。
   - `commissioning_controller.dart` `showHealthPending`：`messageKind == verified`；
     `direct_switch_failed` 清紅框：記下失敗當下的錯誤字串 `_directSwitchError` 再比
     （同一個字串物件，語言切換不影響）。
   - `progress_checklist`、`recent_gateways`、`next_action_guide`、上傳狀態列：B2／B3 已改。
   - 沒有結構化資料、只能「同源比對」的地方改用 `matchesAnyLanguage(text, (l) => l.key)`

     `gateway_mode_card` 與紅框去重、controller 忙碌訊息還原、`_settlePending`、
     `commissioning_page` 第 1 步隱藏「準備完成」／辨識訊息。

   **殘留（刻意保留，理由）**：
   - controller `_sideTask` 的 `state.message == label`：`label` 是同一次呼叫傳入的
     同一個字串，與語言無關。
   - `ptu_selection_tile` `result != statusText`：只為了不重複顯示同一句，語言切換的
     瞬間最多多顯示一行，不影響行為。
   - `verify_live_panel` 原因：`VerifyFeedEntry.reasons` 已是 `List<String>`，只用
     `common_listSeparator` 串接顯示，沒有比對；原因文字是產生當下的語言（§5）。
   - `field_report` `report == _installText`：比的是同一份報告本文（中文），不是畫面字。

3. **同一字串兩語都要能辨識**時（存檔資料、切換前寫入的文字），比對所有
